## Hypothesis
Variant A (proposal "Learnable q and d", per-head scalars): letting each head pick its own (q_h, d_h) by gradient
descent moves the 125M model along the fixed-(q,d) frontier, not off it. The gradient probe says the model wants d
wider than 2 at 125M, so d_h settles in [2.1, 2.6] and the row lands near the fixed q3/d3 cell; q_h barely moves.
This is the control for Variant B (per-query window): if per-head learning alone reached ASEntmax, B would be moot.

## Change
Implemented on this branch (fixed-(q,d) path unchanged; PER_HEAD is a constexpr branch):
- `stieltjes/triton_stieltjes.py`: PER_HEAD mode in all four kernels: per-head q_h, c_h = d_h^-q_h loaded per
  program, runtime pow via exp2/log2, per-head Newton start lam0 = (1+c)^(-1/q) and Newton step; the dQ kernel also
  accumulates per row gd = Σ_A (dP - δ) and gq = Σ_A ∂w/∂q|λ (dP - δ) (implicit-function gradient,
  ∂w/∂q|λ = -ln(λ-s) (λ-s)^-q + ln(d) c, ∂w/∂d|λ = q d^-q-1). `StieltjesAttentionQD` reduces them over batch and
  rows: dL/dd_h = q c/d Σ gd/S, dL/dq_h = Σ gq/S. `stieltjes_attention_qd(q, k, v, head_q, head_d, ...)`.
- `model.py`: `stieltjes_learn_qd` (GPTConfig); parameters `stieltjes_theta_q`, `stieltjes_theta_d` (H,) per layer
  (1-D, so no weight decay); fused path calls the QD kernel; eager/stats path uses the per-head
  `stieltjes_normalize_qd` with the learned values (eval_lengths `--stats_lengths` therefore uses learned q, d).
- `train.py`: config default + model_args key + resume key; a `kind: qd` record (q, d per layer per head) in
  `metrics.jsonl` at every eval. (Brief allows train.py "only to log": the config/model_args plumbing is the minimum

  the theta grads fused vs eager. `tests/test_fixed_path_identical.py` checks the fixed path (q3/d2, q4/d2, q4 dense,
