## Change
- `model.py`: `nape_split()` parses `nape_slope_type='<base>_a<N>'` (N ALiBi heads, default n_head//2);
  `nape_slopes` uses it; `n_scaled` = n_head - N for both `as` and the new `ssmax`. `attn_scale='ssmax'`:
  per-NoPE-head parameter `ssmax_s` (shape (n_scaled,), init N(1, 0.01), 1-D so not weight-decayed), queries times
  s_h * log(pos+2), same position offset as the existing AS path and as asentmax `attn_scale_type=nakanishi`.
- **Deviation from the direction doc:** the doc asks for a config field `nape_n_alibi`. `train.py` builds `model_args`
  from a fixed key list and may not be edited here, so a new field would never reach the model or the checkpoint
  (eval_lengths.py rebuilds the model from `ckpt['model_args']` and would silently evaluate at 6/6). The split is
  therefore carried in `nape_slope_type`, which train.py already passes, saves, and restores on resume. Same semantics.
- `osc/rows.sh`: suffix `_a<N>` (outermost, after `_xs`) -> `--nape_slope_type=exp_a<N>`; base `ssmax`.
- `osc/env.sh`, `osc/lm_array.sbatch`: ported the REPO / VENV override from `direction/lm350m-qdf` (ee9c29f, 4465367),
  identical lines. Without it `run_lm.sh` re-sources env.sh and runs the main checkout's code with the purged
  `venvs/asentmax`. Infrastructure only, outside the doc's file list; no protocol effect.
- Tests: `tests/test_rows.sh` (row strings for old rows unchanged), `tests/test_split_ssmax.py` (old-vs-new bit identity
  against c712396, slope checks, ssmax scale and no-decay), `tests/test_attn_paths.py` gains an `ssmax` row.
- Job: `osc/probe_hs.sbatch`, 1 x nextgen A100 40 GB, 1:15 limit; tests, then 40 steps per row at the production batch
  (micro-batch 16 x 16 softmax, 8 x 32 Stieltjes), num_iter from `$LM_RESULTS/NUM_ITER` (15). Outputs under
  `$LM_RESULTS/125m/hs_probe/`. Estimated 0.5 GPU-h (softmax 6.3 s/step, Stieltjes 13.8 s/step from the 125M runs).
