## Hypothesis
User extension 2026-11-15, item (2). Adaptive-temperature softmax (arXiv 2410.01104) trained in the loop on the NoPE heads
(ALiBi heads plain softmax): each query row's logits are multiplied by beta(H) = where(H > 0.5, max(poly(H), 1), 1), H = the
Shannon entropy of the row's plain softmax. If an entropy-dependent sharpening is enough to hold dispersion off beyond the
train length, adatemp improves on softmax at ArXiv / PG-19 16k; the polynomial was fitted on <= 16 items and returns beta = 1
above H = 5.95 nats, so very diffuse rows at 16k get no correction.

## What was read (paper, local LaTeX `context/adaptive_temp_softmax_latex/`)
- Sec. 4 and the JAX listing (label fig:jax): two softmaxes, `poly_fit = [-0.037, 0.481, -2.3, 4.917, -1.791]` through
  `jnp.polyval`, entropy with `log(p + 1e-9)`, `beta = where(entropy > 0.5, maximum(polyval, 1.0), 1.0)`,
  `softmax(logits * beta)`. No stop_gradient in the listing, so the gradient flows through beta; implemented that way.
- The CLRS-Text paragraph: for Gemma 2B the function is used as-is, the same polynomial, in every head, during fine-tuning
  and at inference. This run trains from scratch and restricts it to the NoPE heads (user instruction); both are departures
  from the paper's setup. I did not find a from-scratch LM result in the sections read (Sec. 4, 5, App. on streaming).
- App. "streamed" algorithm: entropy from running sums inside a flash kernel, O(n) memory. Not implemented as a kernel here.
- Evaluated by hand: beta > 1 only for 0.87 < H < 5.95 nats, peak 2.39 at H = 4.1; beta is continuous at both ends.

## Change
- `model.py`: `attn_scale='adatemp'` (softmax only). On a NoPE head the logits are q.k / sqrt(D) with no bias, so
  softmax(logits * beta) is the existing SDPA path with that head's queries multiplied by beta. beta needs the row entropy:
  `_RowEntropy` (autograd.Function) computes it in fp32 over chunks of query rows (keys below the chunk end only) and its
  analytic backward recomputes each chunk, so no T x T map is stored (one transient block of 2^26 entries, 256 MB).
  `adaptive_temperature_softmax` is the materialised paper function, used by the per-head eager path (`collect_stats`,
  `force_per_head`), where the queries are left unscaled so the two paths are independent.
- `osc/rows.sh`: base `adatemp`. `osc/run_lm.sh`: `MICRO_BATCH=<n>` per manifest line (accumulation 256 / n, 524,288 tok/step).
- Tests (`tests/test_ssmax_adatemp.py`, tier 1 desktop GPU 2026-11-15, ALL OK): beta(H) at 9 hand-evaluated points;
  materialised function vs an independent port of the JAX listing (max diff 1.1e-06, beta > 1 on 75 % of rows); streamed
  entropy vs materialised over 5 chunks (max diff 7e-07, grad rel err 2e-07); whole 2-layer model, training path vs
  per-head materialised path: logits max diff 5e-06, parameter-grad rel err 1.4e-05 (CUDA), beta > 1 on 22 % of rows; ALiBi
  heads equal plain softmax. `tests/test_attn_paths.py` row `adatemp`: fp32 out 7e-07 / 1e-06, bf16 5e-03 / 5e-03.
- Probe before any training (tier 2, debug-nextgen, `osc/probe_adatemp.sbatch`): the tests on the OSC torch / triton;
  train.py tok/s and peak memory for softmax_xs / ssmax_xs at micro-batch 16 and adatemp_xs (streamed) at 16 and 8; per-head
  materialised training at micro-batch 1, 2, 4; 16k eval paths. Decision rule (user): train lr 1.2e-3; add lr 2.4e-3 only if
  one run is <= 15 GPU-h; above 40 GPU-h per run do not submit, pause with the numbers. Extension cap 60 GPU-h incl. e009.
