## Hypothesis
The forward kernel is slow because `tl.static_range(NUM_ITER)` unrolls 15 copies of the Newton sweep into one kernel:
e001 measured a cost per sweep that grows with NUM_ITER (0.5 / 1.3 / 2.0 ms at NUM_ITER 5 / 15 / 30 after removing the
~1 ms launch overhead), where one sweep of this size should cost what the it=0 kernel pays (0.25 ms for row-max +
output). Emitting the loop once (`tl.range`, an `scf.for` in Triton 3.1.0 `code_generator.visit_For`) removes whatever
scales with the copy count (shared memory per block, registers, code size: not yet identified) and makes the forward
affine in NUM_ITER with the same arithmetic in the same order, so outputs and gradients are unchanged.

## Prediction (before submission)
- candidate forward kernel at the training shape, num_iter 15: <= 12 ms against 22.7 ms for the frozen baseline: 55 %;
  at least 20 % faster (<= 18.2 ms): 75 %.
- candidate forward time is affine in NUM_ITER: per-sweep cost from (it=15 - it=5)/10 and (it=30 - it=15)/15 agree
  within 15 %: 80 %.
- 125M step of `wstieltjes_q3_d2_xs` (mb 8 x 32, compile on): >= 20 % lower than the baseline in the same job
  (<= 10.9 s against ~13.6 s): 60 %; at or below ASEntmax's 10.0 s: 50 %. The same ratio within 5 % on
  `aswstieltjes_q3_d2_zi_xs` and `wstieltjes_q4_d2_xs`: 75 %.
- eval forward at (1, 12, 16384, 64): faster by a ratio within 20 % of the training-shape ratio (same MAC rate per
  sweep in e001): 65 %; ArXiv 16k eval tok/s in the gate's e2e up, not down: 85 %.
- gate passes: 85 %. Candidate bit-identical to the frozen baseline (max diff 0 on every case): 65 % (same operations
  in the same order; a different FMA contraction or reduction order from the restructured loop would break identity
  without breaking the gate).
- if the hypothesis is wrong (no speed-up), the compiled-kernel row added to the micro (shared bytes, PTX size per
  variant) says which resource does not scale with the copy count.

## Change
- `stieltjes/triton_stieltjes.py`: `for _it in tl.static_range(NUM_ITER)` -> `for _it in tl.range(0, NUM_ITER)`
  (NUM_ITER stays a constexpr argument, so call sites and the autograd wrapper are untouched), header line and
  docstring updated. Nothing else. `triton_stieltjes_ref.py` untouched.
- `bench_kernel.py micro`: one optional row per compiled forward variant (shared-memory bytes per block, num_warps,
  PTX and cubin size from `JITFunction.cache[...].metadata / .asm`, guarded by try/except) to identify the mechanism.
- Jobs: `osc/kernel_time.sbatch` with `PLAN=ab` (micro, then 3 rows x {frozen baseline, candidate} x 20 steps) and
  `osc/kernel_gate.sbatch`, both `TAG=e002`, debug-nextgen.
- Smoke: `research/experiments/stieltjes-kernel-speed/smoke_e002.sh` through `osc/kernel_smoke.sbatch` (tier 2):
  full-shape micro for both kernels plus `test_kernel_equiv.py --part=random --quick`, from an empty directory.
